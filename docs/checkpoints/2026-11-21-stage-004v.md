Known gaps:
- Callbacks execute on the gateway completion thread (or caller thread for cancel); no main-thread/UI dispatcher.
- No request timeout or watchdog.
- No bounded event queue/streaming.
- No Android transport, React Native NativeModule or Newman adapter.
- No mock HTTPS server integration.
- The current bridge tests are JVM tests, not Android instrumentation tests.

## 4. Next work — do in this order

### Stage 004V-2: lifecycle hardening
1. Introduce an injectable scheduler/timeout abstraction; do not hard-code wall-clock sleeps in tests.
2. Ensure timeout, success, failure and cancel race through the same terminal-state gate; only one callback may escape.
3. Cancel timeout task on any terminal outcome and cancel gateway call on timeout.
4. Introduce an injectable callback dispatcher; provide a direct dispatcher for JVM tests and an Android main-looper dispatcher for app integration.
5. Do not call listener code while holding internal locks. Guard listener exceptions so they cannot corrupt lifecycle state.
6. Add deterministic tests for timeout, success-vs-timeout race, cancel-vs-timeout race, synchronous completion, dispatcher behavior, listener exceptions and timeout-task cleanup.
