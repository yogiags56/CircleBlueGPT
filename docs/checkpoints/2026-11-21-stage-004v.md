## 2. Project intent and hard constraints

Restore the original Cortana Android experience while preserving Cortana's identity, personality, UI and blue-ring persona. Replace the retired Microsoft service/authentication boundary with a modern GPT-backed service.

- Android-first; original Cortana APK is immutable forensic input.
- Zero-login UX is the goal; anonymous device/session enrollment only after security review.
- GPT is the backend brain, not a replacement persona.
- Provider credentials stay on the backend; never embed API keys or production secrets in the APK.
- Local memory must be encrypted and user-controllable; send only selected relevant context.
- Do not reuse Microsoft/Bing tokens, headers, old endpoints or legacy CSDK auth.
- No privileged legacy skills (alarms, calls, SMS, settings) in MVP.
- Keep original APK immutable and excluded from Git.

### Codec contract
- Request v1 fields: `protocolVersion`, `requestId`, optional `conversationId`, `input.text`, `context.selectedMemory`.
- Response v1 fields: `protocolVersion`, matching `requestId`, `message.text`.
- Rejects duplicate/unknown fields, unsupported protocol, mismatched IDs, malformed/trailing JSON, invalid UTF-8, empty/oversized response text.
- Maximum encoded request: 64 KiB.
- Maximum response body: 256 KiB.
- Maximum response text: 65,536 characters.

### HTTP gateway contract
- Endpoint URL is injected; requires HTTPS and rejects userinfo/query/fragment.
- Default connection factory uses platform HTTPS and default TLS certificate validation.
- Background Executor is injected; never run network I/O on Android main thread.
- Fixed-length POST with Content-Type, Accept, Accept-Encoding identity and Idempotency-Key.
- Configurable connect/read timeouts (positive, capped at 120 seconds).
- Redirects disabled; only HTTP 200 accepted.
- Both Content-Length and streaming reads are bounded.
- Generic failure mapping; non-200 error body/provider details are not surfaced.
- Cancellation/completion use one atomic state. Cancellation disconnects an active connection best-effort and suppresses late callbacks.
- No auth header, session token, production URL, retry policy or provider secret is included.

### Test boundary — important
JVM transport tests inject a fake `HttpsURLConnection`. They validate request configuration, response parsing, bounds, redirects, generic errors and cancellation. They do **not** prove a real TLS handshake or end-to-end interoperability with an HTTPS server.
